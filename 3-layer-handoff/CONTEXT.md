# CONTEXT.md

## Purpose

This document defines canonical concepts in the MFHIS meta-project using a **strict semantic stability schema**.

Each term is treated as a **reconstructable ecological object**, not a metaphor, not a description, and not an implementation artifact.

---

# TERM DEFINITIONS

---

## AOR (Artifact of Observation Record)

### 1. Definition (ontological)

AOR is a **structured record of an emergent observational configuration within a bounded session**, capturing how distinctions, gradients, and collapse pressures cohere into a describable topology.

It is not the emergence itself, but the **residual trace of emergence under observation constraints**.

---

### 2. Activation Kernel

> "Record how structure becomes visible under pressure."

---

### 3. Avoid Set

- Log
- Prompt trace
- Analysis report
- Session summary
- Output transcript

These terms introduce **procedural or linguistic drift away from ecological interpretation**.

---

### 4. Relationship Map

- Depends on: Observational Position
- Produces input for: Chronos, TLR
- Co-evolves with: Kairos
- Bound to: Compression regimes (AOR-100, etc.)

---

### 5. Cardinality

- One-to-many (one session → many AORs)

---

## TLR (Trace Lineage Record)

### 1. Definition (ontological)

TLR is a **record of the conditions, pressures, and separations that enabled stabilization events to occur across multiple AORs**.

It does not describe artifacts; it describes the **field of necessity that produced artifacts**.

---

### 2. Activation Kernel

> "Record why stabilization became possible."

---

### 3. Avoid Set

- History log
- Provenance chain (unqualified)
- Dependency tree
- Git lineage
- Causal trace

These introduce **linear or computational ancestry bias**, which reduces ecological interpretation.

---

### 4. Relationship Map

- References: AORs as evidence nodes
- Interacts with: Chronos (validation of persistence conditions)
- Informs: Kairos emergence interpretation
- Extends: Observational Position (across time)

---

### 5. Cardinality

- Many-to-one (multiple AORs → one TLR)
- Hierarchical-many (TLR-100 → TLR-101, etc.)

---

## KAIROS (Aligned Kairos System)

### 1. Definition (ontological)

Kairos is a **detection system for emergence events within an AOR space**, where emergence is defined as a phase transition in observable structure under constraint pressure.

It captures **becoming**, not persistence.

---

### 2. Activation Kernel

> "Detect when structure becomes visible."

---

### 3. Avoid Set

- Generator
- Output engine
- Response system
- Insight model
- Creative transformer

These collapse Kairos into **production rather than detection ecology**.

---

### 4. Relationship Map

- Input: AOR
- Paired with: Chronos (dual axis system)
- Feeds: TLR (emergence conditions)
- Constrained by: Observational Position

---

### 5. Cardinality

- One-to-many (one session → multiple Kairos detections)

---

## CHRONOS (Aligned Chronos System)

### 1. Definition (ontological)

Chronos is a **measurement system for persistence under transformation**, evaluating whether observed structures survive compression, distortion, or reconstruction.

It captures **becoming-stable**, not becoming-visible.

---

### 2. Activation Kernel

> "Measure what survives transformation."

---

### 3. Avoid Set

- Logger
- Validator
- Checker
- Tester
- Serializer (unqualified)

These terms collapse Chronos into **engineering instrumentation instead of ecological measurement**.

---

### 4. Relationship Map

- Input: AOR-derived structures
- Paired with: Kairos (dual axis system)
- Feeds: TLR (stability conditions)
- Defines: collapse pressure gradients

---

### 5. Cardinality

- One-to-many (one structure → multiple compression evaluations)

---

## OBSERVATIONAL POSITION

### 1. Definition (ontological)

Observational Position is the **set of constraints defining what distinctions can be perceived within a session ecology**.

It is not a viewpoint; it is a **structural limitation field**.

---

### 2. Activation Kernel

> "What can be distinguished from here?"

---

### 3. Avoid Set

- Perspective
- Viewpoint
- Lens
- Frame
- Context window

These imply subjective agency rather than structural constraint.

---

### 4. Relationship Map

- Governs: AOR formation
- Constrains: Kairos detection sensitivity
- Influences: Chronos compression fidelity
- Recorded in: TLR (indirectly)

---

### 5. Cardinality

- One-to-one per session state (can shift over time)

---

## COLLAPSE PRESSURE

### 1. Definition (ontological)

Collapse Pressure is a **force indicating instability in a configuration of distinctions under transformation or compression**.

It is not failure; it is **redistribution potential**.

---

### 2. Activation Kernel

> "Where structure becomes unstable under change."

---

### 3. Avoid Set

- Error
- Failure
- Noise
- Bug
- Loss

These misinterpret redistribution as degradation.

---

### 4. Relationship Map

- Acts on: AOR, Kairos outputs, Chronos evaluations
- Recorded in: TLR as field condition
- Modulates: Observational Position drift

---

### 5. Cardinality

- Many-to-many across all system components

---

## CONTEXT MAP RULES (MULTI-CONTEXT SYSTEM)

When multiple contexts are active:

### 1. Event Propagation

A change in one AOR propagates through:

- Kairos (emergence detection shift)
- Chronos (persistence evaluation shift)
- TLR (lineage reinterpretation)

---

### 2. Shared Identity References

- AOR-IDs must remain stable across sessions
- TLR-IDs must reference AOR clusters, not individual outputs
- Kairos/Chronos evaluations must reference AOR origin point

---

### 3. Boundary Constraints

- No synonym substitution allowed across contexts
- No implicit merging of lineage and sufficiency systems
- No untracked observational position shifts

---
